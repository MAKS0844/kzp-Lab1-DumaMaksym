# Звіт до лабораторної роботи № 2

## 1. Тема, номер і варіант
Предметна область: Каталог фільмів.
Номер варіанта: 8.
Операційна система: Windows.

## 2. Мета роботи
Перебудувати предметну частину продукту: замість рядків і паралельних змінних використати власні класи, перевірку стану об'єктів, record для незмінного допоміжного значення та тести, які підтверджують збереження зовнішньої поведінки.

## 3. Стан до і після цієї роботи
**До:** Запис існував як масив `String[]`. Валідація та перетворення (parseInt) відбувалися безпосередньо в циклі парсингу у класі `Main`.
**Після:** Створено повністю незмінний клас `Movie` з інкапсульованою валідацією. Логіку розбиття рядка перенесено до статичного методу `fromCsv`. Змінні для статистики замінено на компактний `record MovieSummary`.

## 4. Клас-сутність (та патерн Builder)
Клас `Movie` містить `private final` поля. Для виконання завдання із зірочкою створено внутрішній клас `Builder` для зручного покрокового конструювання об'єктів. Щоб Builder не міг обійти валідацію, всі перевірки інваріантів відбуваються безпосередньо у приватному конструкторі `Movie`, який викликається методом `build()`. Метод `toString` форматує вивід через `Locale.ROOT`.

## 5. Фабричний метод і record
Фабричний метод `fromCsv` перевіряє кількість полів, перехоплює помилки парсингу чисел (`NumberFormatException`) і використовує `Builder` для створення об'єкта `Movie`. 
Підсумки обчислень зберігаються у `record MovieSummary`, який перевіряє коректність математичних результатів у власному конструкторі.

## 6. Тестування
До старих тестів додано перевірки для:
- Конструювання `Movie` з коректними даними.
- Відхилення негативних/нульових значень (напр., тривалості) конструктором.
- Відхилення `NumberFormatException` та неправильної кількості полів у `fromCsv`.
- Перевірку рівності (Value Equality) об'єктів типу `MovieSummary`.

## 7. Інфраструктура
Збірка виконується командами `test`, `verify`, `package`. Збережено попередню конфігурацію Maven. CI/CD працює через GitHub Actions, перевіряючи код на трьох ОС та зберігаючи артефакт.
